# Two-way browser voice repair

Reproduced a real Chrome failure using the shared `VoiceClient` and `PeerMesh`: both players reported Connected and live microphones, while the first player's incoming playback measured zero. The answering browser created an audio transceiver before applying the remote offer. That sender was not associated with the offered media section, so attaching its microphone did not transmit audio.

The offerer now creates the audio transceiver; the answerer uses the transceiver created by `setRemoteDescription`, sets it to `sendrecv`, and attaches the current microphone before answering. Both directions stay negotiated when voice is initially off, so joining, muting, and rejoining do not require renegotiation. This follows the [WebRTC transceiver association rules](https://www.w3.org/TR/webrtc/).

## Validation

- `npm run test:voice:browser`: two isolated Chrome contexts, real WebRTC, real shared voice clients, generated microphone tones. Measures audio after the playback gain node in both directions. Checks mute/re-enable, incoming mute, per-player volume, suspended playback recovery, and leave/rejoin. Asserts exactly one negotiated `sendrecv` transceiver on each side. The original implementation failed the incoming-audio assertion; the repair passes.
- `npm run test:voice:browser -- --early`: same checks, with microphone publication before signaling is released to negotiate the connection.
- `node scripts/test.mjs shared/voice shared/peer`: 34 tests passed.
- `node scripts/peer-integration.mjs stack-or-sink`: four native WebRTC clients, game data, generated audio, abrupt host recovery, preserved round state, surviving voice, and graceful handover passed.
- `npm run typecheck`: passed. Scoped formatting and lint passed.

The browser test uses an in-memory coordinator store and local ICE candidates, leaving public rooms untouched. It tests the actual browser playback graph, not physical speakers or microphones, the React panel, or two separate internet connections. The fix is in the local workspace and has not been deployed. TURN remains necessary on networks that cannot establish direct peer connections.
