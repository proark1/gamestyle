# Sound workshop and speaking

Uphill Delivery also has its sound creator at `/uphill-delivery/admin`, linked from the depot and in-game help. It shares the collection narrator and offers **Reuse missing sounds & music** for existing Stack or Sink or Blend Business clips. Reuse keeps existing delivery edits and files, uses the original saved MP3s, and does not generate or spend credits. Game-specific dialogue keeps its own words. The delivery library contains 74 cues: the original 30 plus 44 material and environment details.

Open `/stack-or-sink/admin`, `/act-natural/admin`, `/uphill-delivery/admin` or `/dont-wake-the-giant/admin`, or use the music-note button on each game's menu. There are 121 Stack or Sink cues, 77 Blend Business cues, 74 Uphill Delivery cues and 65 Tiptoe Thieves cues. Generated sound prompts are documented in [audio-prompts.md](audio-prompts.md).

Blend Business includes original bundled WAV defaults for the powered-fence warning hum and contact zap. They work without a provider key or generated recordings, follow the saved mixer and per-cue volumes, and yield to workshop recordings when available. The new `event.fence-shock` cue is editable in the workshop. Regenerate the bundled originals with `node games/act-natural/scripts/generate-fence-audio.mjs`.

Stack or Sink adds 51 cinematic cues: distant gulls, palm rustle, draining water, material strain, loaded cable movement, surface-specific landings, alternate impacts, two gameplay scores and a rescue accent. Height and water proximity shape the mix. New music and landings fall back to the original recordings until generated. Preview the missing recordings with `node --import tsx games/stack-or-sink/scripts/stack-audio-generation.mjs https://jumbleyard.up.railway.app`; append `--generate` after publishing this catalog to use the workshop's saved provider key. Existing files and edits are preserved.

Blend Business adds grass brushing, carried-ladder creaks, trough water laps and tree wing flutters (three takes each). Farm animal and environment details receive downward-only playback level conditioning; the original files and saved mixer values are kept. Workshop previews play the original recording, while gameplay also applies conditioning, distance and activity levels. `games/act-natural/scripts/farm-audio-generation.mjs` previews only these twelve additions by default; `--generate` generates missing files with the saved workshop key, and `--all-details` includes the earlier 21 details too. Existing saved files are always skipped.

## Generate sounds

All workshops include **Voice design** with The Chaos Commentator prompt already filled in. If a narrator is already selected, Uphill Delivery and Tiptoe Thieves inherit that saved voice by default; no new audition is required. To change the collection narrator, save an ElevenLabs key, generate auditions, listen and choose **Use this voice for the collection**. This applies the saved narrator to all four speech libraries. The selected voice uses the owning game's key; a game without its own key can also use that shared key. Keys and volume mixes remain separate.

Use **Spoken text** to generate, listen to and download any standalone English line. **Edit gameplay dialogue** opens the speech cues; edit their separate speech text and generate them to hear the narrator during play. Selecting a new voice marks existing speech outdated. Auditions and standalone text use credits, and their latest saved results can be reopened from either workshop.

Workshops require an administrator password on both local and hosted games. Set `AUDIO_ADMIN_PASSWORD` to a unique, randomly generated password of 16–256 characters in the server environment (a Worker secret on Cloudflare), then sign in on the workshop page. With no configured password, editing and generation are disabled. Public playback and existing recordings continue to work. The password stays in the open page's memory; reloading signs out. Use HTTPS when hosted, and rotate the server value to revoke access.

The administrator password is separate from the ElevenLabs API key. Enter an ElevenLabs key separately in each library, check the connection, select a voice, and save the mix. ElevenLabs usage is charged to that key. No sounds are automatically generated by gameplay or deployment. Workshop command-line scripts read `AUDIO_ADMIN_PASSWORD` from their environment, use it only for workshop API requests, and reject credential-bearing redirects. Never put either secret in source code, browser storage, a public environment variable, or command-line arguments.

The per-sound player previews the saved file at its selected gain. Save volume changes without generating again. A changed prompt marks its current file outdated. Generate missing/outdated preserves completed work and stops on errors. Stop requests cancellation of the active job as well as clearing the remaining queue; already-started provider work may still be charged. Keep the workshop tab open while generating.

Node stores encrypted keys and cue settings in the existing SQLite database, and MP3 files in the adjacent `audio/` directory. Its `.master-key` must be backed up with the database and audio. Optionally provide a 64-digit hexadecimal `AUDIO_MASTER_KEY`. On Cloudflare, configure that secret and the R2 `AUDIO` binding alongside D1 `DB`. New migrations are applied through the existing deployment process. Never put server keys into public environment variables or source code.

Audio unlocks after a player interaction. Gameplay refreshes published sounds within 30 seconds. Missing clips stay silent. Footsteps follow movement and use three takes per surface; ambience and music crossfade, voices lower background loops, distant events are quieter, and hidden tabs suspend audio. The sound toggle controls game audio; incoming voice has a separate mute control.

## Player-hosted voice

New rooms use direct WebRTC voice and browser-hosted gameplay across all four games. LiveKit is not needed for these rooms. Run `npm run dev:peer -- --port 3012` for a Node preview using the separate `data/peer-preview.sqlite` database. The normal Cloudflare development and hosting path also supports peer rooms. Microphone access requires HTTPS or localhost.

The host automatically passes to the earliest-joined connected player after a departure. See [host handover](host-handover.md) for timing, checkpoint recovery and the shared coordinator's role. The web application and coordinator must be hosted independently for recovery to work when a player's entire PC shuts down.

All four games have the same top-right toolbar: Voice, game sound, help, All games, and Leave game while playing. The Voice button remains visible on menus and in solo practice, where it explains how to join multiplayer. Existing sound workshops remain accessible on the start screens.

Create or join a multiplayer room, select **Voice**, then **Join voice**. This explicitly requests microphone access and starts an open microphone when permission is granted. **Listen only** joins without requesting microphone access. Mute or enable your microphone in the same panel. For push-to-talk, select that speaking mode, enable the microphone, then hold T or the touch talk button. Releasing the button, losing focus, or hiding the tab stops transmission; an open microphone must be enabled again after losing focus. Device selection, a microphone level meter and personal volume controls are included. If the browser blocks playback, select **Enable voice playback**. Permission denial keeps listening available and shows a recovery instruction.

Each game has its own voice room. Blend Business uses equal room voice to avoid revealing hidden cow identities; Stack or Sink optionally makes distant voices quieter. Incoming speech lowers game audio across all four games. No recording is implemented.

Run `npm run test:peer` for four-client real WebRTC and generated-audio checks for all four games. Set `PEER_TEST_URL` to a running game origin to include the real HTTP coordinator and database.

## Internet connectivity

The default uses STUN to establish direct peer connections. Some mobile, corporate and restrictive home networks need a TURN relay. Configure these runtime values on the coordinator before relying on cross-network connectivity:

```text
PEER_TURN_URLS=turn:your-relay.example:3478,turns:your-relay.example:5349
PEER_TURN_USERNAME=<relay username>
PEER_TURN_CREDENTIAL=<relay password>
```

These are example placeholders, not a provisioned relay. No TURN service is configured by this change. Use a properly managed relay account; the ICE credentials are delivered to authenticated room members because browsers need them. Keep configuration out of source and do not use credentials for unrelated services. TURN forwards encrypted WebRTC traffic when a direct connection fails; the elected player's browser still runs the game. Use a public HTTPS coordinator with `PUBLIC_GAME_ORIGIN` matching that origin on Node behind a proxy.

## Legacy LiveKit rooms

Previously created server-hosted rooms retain LiveKit support on Node. `npm run dev:voice -- --port 3012` starts the old local LiveKit setup on ports 18880–18882; install its checksum-verified Windows binary with `powershell -File scripts/setup-voice.ps1` if needed, or set `LIVEKIT_BINARY`. Development credentials must never be used on the internet. Hosted legacy rooms require `LIVEKIT_URL`, `LIVEKIT_API_KEY`, `LIVEKIT_API_SECRET` and the existing membership reconciliation service. Cloudflare still disables this legacy provider path. New peer rooms work independently of those settings. `scripts/voice-integration.mjs` tests only that legacy setup.

Realism must be assessed after generation: preview each sound, remove leading silence, listen to repeated footsteps and loop seams, balance on speakers and headphones, and confirm speech stays intelligible over surf or wind. A four-person, two-network microphone playtest and mobile autoplay check remain necessary before claiming acoustic/device validation.
